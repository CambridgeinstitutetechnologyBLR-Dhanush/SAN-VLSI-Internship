# SAN VLSI Internship — Task 2 Command Log

## 1. Compile the RTL and testbench

**Command:**
```bash
iverilog -Wall -o simulation.out rtl/counter.v rtl/register.v tb/counter_register_tb.v
```

**Explanation:** Compiles the counter RTL, register RTL, and testbench into the simulation executable `simulation.out`. The `-Wall` option enables additional compiler warnings.

## 2. Run the simulation

**Command:**
```bash
vvp simulation.out
```

**Explanation:** Executes the compiled simulation and prints monitored signal values, including reset, enable, counter output, and register output.

**Simulation termination:** The testbench calls `$finish;` after completing all test cases. This terminates the simulation automatically instead of allowing the clock generator to run indefinitely.

## 3. Generate waveform data

**Verilog system tasks in the testbench:**
```verilog
$dumpfile("waveform/counter_register.vcd");
$dumpvars(0, counter_register_tb);
```

**Explanation:** These system tasks generate a VCD (Value Change Dump) file containing signal transitions for waveform inspection. They are included in the testbench and are not terminal commands.

## 4. Open the waveform

**Command:**
```bash
gtkwave waveform/counter_register.vcd
```

**Explanation:** Opens the VCD file in GTKWave so the clock, reset, enable, data, counter, and register signals can be inspected.

## Verification observations

- Reset clears the counter and register to zero.
- The counter increments on rising clock edges when enabled.
- The counter holds its value when disabled.
- The register captures input data on a rising clock edge when enabled.
- The 4-bit counter wraps from 15 (hexadecimal F) to 0.
- The simulation terminates automatically after all test cases complete.

## Result

The counter and register were simulated using Icarus Verilog, and their signal transitions were inspected in GTKWave. The expected reset, enable, hold, and counter wraparound behaviors were verified.
